# 下单方式对比：本模组面板 vs ME 终端

MekCK 的机器有**两条完全独立**的下单通道。它们能做的事情看起来相似，但**限制完全不同**——尤其是大批量。

## 一句话结论

* **小批量、要和其他 AE2 合成混在一起** → 用 **ME 终端下单**（需要合成 CPU）。
* **大宗生产（成千上万、上亿件）** → 用 **本模组面板下单**：不需要合成 CPU，也不受 CPU 字节容量限制。

## 对照表

| | **本模组面板下单** | **ME 终端下单** |
|---|---|---|
| 入口 | 工厂类：「订单」面板表头的 **本机 / ME** 按钮；其余机器：左侧 **「下单」tab**（侧配 tab 下方） | ME 终端的合成界面 |
| 支持范围 | **上表之外，几乎所有能接 ME 的机器都已接入**（含 17 台联动机器）；只有三明治组装机与生物反应堆没有面板入口 | 见 [[network/me-ordering.md|ME 终端下单]] 的支持清单 |
| 缺料提示 | 选中配方后在数量区下方用**红字**列出「缺少 X×N」（按当前数量算） | 在合成状态里列出缺少的材料 |
| 需要合成 CPU？ | **不需要** | **需要**，且必须空闲 |
| 受 CPU 字节限制？ | **不受** | **受**：`计划字节 ≤ CPU 可用字节` |
| 单次数量 | 一次可下 `quantity` 份（面板有 1 / 16 / 32 / 64 / 自定义 / **最大**） | 一次推送 = **1 次合成**，大订单靠 AE2 反复推送累积 |
| 上限由什么决定 | 机器槽位（单槽最多 21.47 亿 × 槽数） | AE2 合成 CPU 的字节容量 |
| 材料从哪来 | 直接 `MEStorage.extract`（或机器本地库存） | CPU 先把材料抽进自己的库存，再交给机器 |
| 适合 | **大宗量产**、无限 ME、长时间跑量 | 与小批量合成混排、自动补货、和 AE2 其他合成统一排队 |

## 为什么大宗要用我们的面板：AE2 的字节规则

AE2 的合成 CPU 容量以**字节**计，一次合成计划所需的字节约为：

> **字节 ≈ 合成次数 + 8 × 合成树节点数**
> （每条样板执行 1 次记 1 字节；合成树里每个中间物品节点另加 8 字节固定开销）

| CPU 合成存储 | 字节 | 大致能下单的产物数 |
|---|---|---|
| 1k | 1024 | ≈ 1000 件 |
| 16k | 16384 | ≈ 1.6 万件 |
| 64k | 65536 | ≈ 6.5 万件 |
| 256k | 262144 | ≈ 26 万件 |
| **21 亿件** | **≈ 21 亿** | 需要约 **8192 个 256k 存储单元** ⇒ 实际上做不到 |

也就是说：**用 ME 终端下几百万、上亿件的订单，先卡死的不是机器而是 CPU 容量**；而本模组面板直接操作 ME 网络，**没有这道墙**——上限只取决于机器有多少槽位（单槽 21.47 亿）。

## 大宗生产的推荐做法

1. 打开机器界面：工厂类点「订单」面板里的 **「ME」**；其余机器（含联动机器、独立机器）点左侧
   **「下单」tab**（图标与排序按钮同款，位于侧配 tab 下方）。需要装 AE2 并连上网络；
2. 用**搜索框**找配方（按产物名 / 注册名过滤），选中后点数量区里的 **「最大」**（按网络库存算出可做次数），
   或选 64 / 自定义输入一个大数字；数量区下方会实时显示**缺料红字**「缺少 X×N」，材料够则显示「最大: N」；
3. 点确认下单：机器一次从网络抽取这么多材料，然后按自己的并行/速度加工；
4. 想**长期不断供**，再打开 ME拉 旁的 **「自动」** 按钮做持续补料（补料上限见配置 `auto_pull.auto_pull_stack_limit`）。

## 什么时候仍然用 ME 终端

* 你要做的成品**需要别的机器的中间产物**（终端能顺着合成链把子合成一起排进去）；
* 你想让机器的产出**和 AE2 其它合成统一排队、统一进度显示**；
* 只是偶尔做几十几百件，且网络里已经有空闲 CPU。

## 常见误区

* ❌「终端下单也能一次灌 21 亿」——不行：既受 CPU 字节限制，也受"一次推送只做 1 次合成"的限制。
* ❌「面板下单要造合成 CPU」——不用：面板走的是本模组自己的通道，全程不提交 AE2 合成任务。
* ✅「机器接 ME 网络」两种通道都需要（都要连上网络、机器占用 8 频道）。
