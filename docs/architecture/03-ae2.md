## 一、两条路，别混

| 路 | 触发 | 落点 | 入口 | 机器侧需实现 |
|---|---|---|---|---|
| **A. 网络拉料 / 自动补料** | 玩家点「网络拉料」tab，或勾「自动补料」 | 机器**输入槽** | `MekckAe2.pullNetworkInputs` | `ae2/INetworkPullable` |
| **B. ME 终端下单** | 玩家在 ME 终端下样板 | 机器**端口窗口** | `pushPattern → insertIntoMachine → insertIntoPortWindow → startOrder` | `machine/ports/IMekCkPorted` |

### 1.1 路 A：`INetworkPullable`（**不引用任何 AE2 类**）

- AE2 交互全部经 `MekckAe2` 反射门面；未装 AE2 时接口照常存在、只是没人调。
- 必须实现：`getNetworkPullable` / `getNetworkPullInputs`(`List<AE2InputSpec>`) / `getInputSlotRange` / `getNetworkPullItems` / `supportsAutoPull`。
- 可选覆写：`getExtraInputSlots`（输入槽不连续时）、`isMeOrderEnabled`/`setMeOrderEnabled`、`getAutoPullStackLimit`。
- **缺口已关闭**：`MekCkMachineTile:123` **已 `implements INetworkPullable`**，工厂家族两枚 tab 由 `MekCkFactoryScreenBase.addNetworkPullTabs` 挂回。
- GUI 侧 tab 走 `client/MekCkPullTab`（`extends GuiTabElementType`，**零覆写**）+ `NetworkPullButton.register(gui,pos)`；**不要**自己写 tab 类或自画图标框。

### 1.2 路 B：`IMekCkPorted` 端口声明

- 新 tile（6 工厂家族 + 电力烧烤架）**没有 `ItemStackHandler` 存储区**，输入槽是 Mek 的 `IInventorySlot`，所以路 A 对它们**没有落点**，自动化全走路 B。
- `IMekCkPorted` 的签名刻意对齐外部 mod **Mek Energistics** 的 `IMePatternAutomationHost`（对方目标 1.21.1/NeoForge，与本项目 1.20.1/Forge 无交集、无法编译期依赖）——**本期不实现桥接，只是留门**。
- 参数用 `IInventorySlot`（槽对象）而非下标，因而**没有** `INetworkPullable.getExtraInputSlots()` 那种「两段不连续」的债。
- 关键方法：`mePatternItemInputs` / `mePatternItemOutputs` / `mePersistentItemInputs` / `meManualOnlyItemSlots` / `meGroupParallelItemInputs` / `mePortedTile`。
- `MekckAe2.autoWindow(be)` 从 `IMekCkPorted` 取 `MekPortWindow`。

## 三、⚠️ 反射按名取用的成员名清单（**永不重命名**）

| 成员 | 接收者 | 取用方式 | 后果 |
|---|---|---|---|
| `setOrder` | 机器 BE/tile | `Reflect.method(machine.getClass(), "setOrder", …)` | 改名 → 运行期静默失效 |
| `getOrderRecipeId` | 机器 BE/tile | 同上 | 同上 |
| `getOrderQuantity` | 机器 BE/tile | 同上 | 同上 |
| 外部模组配方字段 | `Recipe<?>` / 外部 BE / AE2 对象 | `Reflect.call(obj, "name")` | 同上 |

> 接收者是**表达式**（`machine.getClass()`）而非标识符，**无法做静态类型校验**——STATUS §六记载了一次尝试做「反射取用护栏」并**失败撤掉**的经历。⇒ 可靠做法只有：**约定 + 迁移时不改名**。

## 四、迁移铁律：`instanceof` 分支**先判死活，再决定删还是改指**

`MekckAe2` 里仍有一批按**旧 BE 类型**派发的 `instanceof` 分支（`FactoryGridHost.getItems()` / `getOutputSlots()` / `getReturnSlots()` 等）。

> ⚠️ **本节原先写的是「每台机器迁移时，它对应的分支必须删除」，该规则已被证伪**（口径 §12.4.1，2026-10-06 补记）：
> 删分支前必须先问「这条分支带的是不是活功能」。带活功能的（ME 终端样板 `refreshPatterns`、
> 下单 `startOrder`、投料/产物回网 `getItems`/`getOutputSlots`）**改指新 tile 类型**——
> 删掉它们，那台机器就会在 ME 终端与面板「ME」列表里**静默消失**，编译通过、护栏全绿。
> **实证**：电力研磨机（阶段 3 样板）当年把这四条整条删了，它的 ME 终端样板至今为空。
>
> 只有「功能真的搬走了」的分支才删：侧配 → `TileComponentConfig`（`SideConfigPacket` 那一支）、
> 升级 → `TileComponentUpgrade`（`UpgradeInstallHandler` 对已迁机器的那些分支）。
> 已迁三台单机的处置：电力研磨机（4 条**误删**，能力缺失）、坚果爆炒机（4 条改指，另删 2 条）、
> 急冻制冰机（4 条改指 + 3 条不在本文件里的活分支改指，只删 `SideConfigPacket` 一条）。
>
> 护栏的边界同时也就清楚了：`TestMigrationCompleteness#migratedMachinesHaveNoLeftoverLegacyTypeReferences`
> 禁的是**已删除的旧类名**（`LEGACY_TYPES` 表），不是「还有人引用这台机器」。
